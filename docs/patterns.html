Code patterns

Keep it predictable.

Small modules, shared helpers, and clear failures.

Imports and versions

Use .js in relative ESM imports, even in TypeScript. Use the official semver package; don’t parse versions yourself.

import { getAllResolvedVersions } from "../fs/readLockfile.js";

const versions = getAllResolvedVersions(lockfile, packageName);

Inspect all resolved versions, not just the root. Keep tests for nested dependencies.

Errors

Use the error classes in src/util/errors.ts. Explain what failed and what the user can do.

import { PackageJsonError } from "../util/errors.js";

throw new PackageJsonError("Cannot read package.json. Check the project directory.");

See error handling and cleanup.

Logging

import { logger } from "../util/logger.js";

logger.info("Analyzing overrides...");
logger.success("Lockfile regenerated");
logger.warn("Could not verify this override");
logger.error("Cannot read package-lock.json");
logger.debug("Extra details for library callers");

Debug output is enabled programmatically, not with a CLI flag.

Run subprocesses safely

Production code uses src/util/exec.ts. Pass the executable and arguments separately, without a shell command string.

import { execFile, execFileSafe } from "../util/exec.js";

// Throws on failure.
const result = await execFile("npm", ["--version"], { cwd });

// Returns a success flag instead.
const checked = await execFileSafe("npm", ["--version"], { cwd });

Always clean up

const workspace = await createTempWorkspace(cwd);
try {
  // Run the isolated check.
} finally {
  await workspace.cleanup();
}

Keep project writes in the fix path. Never turn a failed check into a redundant verdict.
