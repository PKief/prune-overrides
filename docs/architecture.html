Architecture

Let npm resolve. Then compare.

Use real npm resolution in isolated workspaces, not guesses about version ranges.

The scan

  1. Read the project’s overrides and lockfile. Keep nested rules and version selectors intact.
  2. Reproduce the baseline with npm in a temporary workspace.
  3. Remove one override in another workspace and regenerate its lockfile.
  4. Compare every resolved version of the target package, including nested copies.
  5. Check that redundant candidates are also safe to remove together.
  6. Show the verdicts and clean up the workspaces.
npm install --package-lock-only --ignore-scripts

Workspaces use the project’s lockfile and npm configuration. No dependency scripts run.

Never check only the root package. A nested dependency can fall back to an older version even when the root version stays the same.

What counts as safe?

The CLI uses no-downgrade: unchanged versions are safe; new versions must not be older than the highest override-enabled version. A different package-instance count alone is not a failure.

Dependency conflicts mean required. Network, authentication, timeout, or invalid lockfile failures mean unknown. Neither is removed.

The library also offers exact (same target-package identities) and full-tree (same identities across the tree). These are not CLI options.

The fix

Reproduce the baseline again and validate the whole removal set. Only then edit package.json and regenerate package-lock.json. Restore both files if generation fails.

Where the code lives

src/bin/ and src/cli/
Entry point, arguments, scan, and fix.
src/analyzer/
Override rules, isolated checks, and removal validation.
src/compare/
Compare versions and package identities.
src/fs/ and src/npm/
Read files, manage workspaces, and run npm.
src/report/ and src/util/
Output, errors, subprocess helpers, and semver utilities.
src/index.ts
Public library exports.

Errors and cleanup

Use PruneOverridesError and its package, lockfile, npm, workspace, or configuration subclasses. Keep messages actionable. Always clean up temporary workspaces in finally.

Limits

npm only, lockfile v2+, and platform-specific results. Relative or workspace dependencies may not be reproducible safely. Version checks do not look up CVEs.
