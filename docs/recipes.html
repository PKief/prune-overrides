Development

Small tools. Direct tests.

TypeScript for checking and building. Node for testing. No lint, formatting, or hook setup.

Build and test

npm ci
npm run typecheck
npm test
npm run build
npm run test:coverage

Development requires Node 26+. Run nvm use to select it. TypeScript tests run natively without a stripping flag.

tsconfig.json checks source and tests. tsconfig.build.json emits production files to dist/, without tests.

Run one test

node --import ./scripts/loader.js \
  --test src/util/semver.test.ts

Tests live beside source: sample.ts and sample.test.ts. Use node:test, node:assert/strict, and scoped mocks.

The loader maps relative .js imports to TypeScript source. Tests run directly, without a test output directory.

Change the analyzer

  1. Start in src/analyzer/analyzeSingle.ts for individual checks.
  2. Add tests for root and nested dependency versions.
  3. Test scanning and fixing on a real project.
  4. Update how it works when behavior changes.

Keep the CLI limited to scan, --fix, --help, and --version. Preserve baseline validation, combined-removal checks, and rollback.

Try the built CLI

cd /path/to/your-project
node /path/to/prune-overrides/dist/bin/prune-overrides.js
node /path/to/prune-overrides/dist/bin/prune-overrides.js --fix

Use a disposable project when testing fixes.

Add an error

Define it in src/util/errors.ts, export it from src/index.ts, and use it where the failure happens.

Publish these docs

In GitHub’s repository settings, open Pages. Choose Deploy from a branch, select main and /docs, then save.

No build step is needed. Preview locally by opening docs/index.html in a browser.
